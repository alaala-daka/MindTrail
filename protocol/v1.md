# MindTrail 事件协议与任务生命周期 v1

## 范围

本规格规定原始事件、两种写入方式、持久确认、续传及 MCP 映射。后续按本机 HTTP 和 SQLite、MCP、端到端、产品化接入。应用继续用 `projectSession` 投影单任务有序事件前缀，内置演示保留原有行为。

## 事件和生命周期

闰秒校验先按时区偏移换算为 UTC，仅允许 UTC 月末 23:59 的秒值为 60；不查询历史闰秒表，因此接受潜在的月末闰秒。普通闰日按公历日期规则校验。

事件信封继续使用 `{v:1,session,seq,ts,type,payload}`。session 为区分大小写的非空标识（建议新任务由调用方生成 UUID），seq 为从 1 开始的连续正安全整数（上限 2^53−1），ts 为带时区的 RFC 3339 字符串，只用于显示和证据。服务端按 seq 排序，保留原 ts。所有请求拒绝重复 JSON 对象键、未知字段、未知版本和未知事件类型。可选字段省略，null 不合法。必填标识和标题等必填文本须含非空白字符，统计值须为非负安全整数。

| type | payload |
| --- | --- |
| task.start | title, goal, project |
| capability.intent | id, title, summary? |
| capability.done | id, summary? |
| api.expose | id, capabilityId?, kind: http/cli/fn, signature, summary? |
| file.change | id, capabilityId?, path, action: create/modify/delete, purpose?, stats: {add,del} |
| call.edge | from, to, kind: calls/imports |
| task.done | summary? |

所有 payload 均可含 quote 和 context。节点 ID 保留 root 和 unassigned 给投影；不同节点类型不得复用同一 ID。capability.done 引用已有能力。call.edge 使用已有 API 或文件节点 ID。缺失或无法解析的 capabilityId 继续沿用桌面投影的未归属分组。节点事实以事件为准，重放严格应用同一输入顺序。project、path、quote、context 都是数据，写入时不执行路径访问或分析。

不存在的任务只有 seq=1 的 task.start 能创建。创建后 running，只允许一个 task.start；task.done 是最后一个新事件并将任务永久转为 done。关闭客户端、断连、崩溃和超时均保留 running；显式重新打开需创建另一 session。done 任务仍可读取和确认过去的相同写入。未完成能力不阻挡任务结束，投影保留真实状态。

## 本机网关

网关监听 `127.0.0.1`，默认端口 `7391`，端口被占用时自动递增。启动时生成随机 token，并将端口、token、协议版本写入发现文件 `~/.path-tracker/endpoint.json`；生产者通过该文件发现网关，端口变化时每秒重读。所有 v1 请求均须携带 `Authorization: Bearer <token>`。`GET /v1/health` 用于健康检查及端口、版本协商。发现文件附带数据库实例生成并持久保存的 store_id，进程重启保留，换库时变化。生产者绑定首个已知 store_id，收到不同值时暂停续传并呈现错误。发现文件必须原子替换。健康检查返回协议版本及 store_id；所有 v1 端点要求鉴权。写入上限为每批 200 条，HTTP 请求体上限 1 MiB。

### 客户端显式序号

`POST /v1/events` 接受非空 JSON 数组。所有元素同 session，按 seq 严格递增，批内相同 seq 返回 400。session 创建时绑定显式序号模式。该模式由一个逻辑写者分配和持久保存序号，可有多个传输进程重试同一个已持久化批次。

服务器在单个事务中逐条处理。已存在的 seq 对完整解析事件进行结构相等比较：对象键顺序和 JSON 空白不参与比较，字符串值（包括 ts 拼法）、字段存在性和数组顺序参与比较。相同内容计入 duplicates，内容变化返回 409 seq_conflict。新事件须等于事务内当前游标 +1，跳号返回 409 seq_gap，携带 expected_seq、offending_seq 与事务前 last_seq。重试可以带上任意已确认的相同事件，只要新增部分连续。第一个错误回滚整批，包含批中先前通过的事件和生命周期变化。

成功返回 200 和 `{accepted,duplicates,last_seq}`。accepted 是本次新增数量，duplicates 是本批已存在且一致的数量，两者之和等于本批长度。last_seq 是本事务观察到的已提交连续高水位，允许高于请求最大 seq。它可指导读取与补发，生产者只能依据本次请求的成功回执删除本次发送的条目。

### 网关分配序号

`POST /v1/append` 接受非空 JSON 数组，元素为 `{v:1,session,operation_id,ts,type,payload}`。所有元素同 session，operation_id 为非空标识（建议 UUID），批内唯一。session 创建时绑定网关分配模式。任一端点写入对方模式的现有 session 返回 409 write_mode_conflict。

网关按请求数组顺序在同一写事务中处理。已存在的 (session, operation_id) 使用完整输入结构比较并返回原分配 seq，相同键不同内容返回 409 operation_conflict。新事件取得当前 last_seq+1，并应用同一生命周期约束。并发写者由数据库事务串行分配，禁止在事务外预留序号；不同生产者的先后取决于事务提交，依赖另一生产者事件的操作应等待前置提交。先提交的 task.done 将任务关闭，竞争中的后续新事件返回 409 task_closed。网关不会从 MCP 进程连接或 tool call ID 推导任务 ID 或操作 ID。

成功返回 200 和 `{accepted,duplicates,last_seq,results:[{operation_id,seq}]}`，results 按输入顺序，含重复项原序号。分配与操作映射同事务持久化。数据库写锁或 I/O 暂时不可用返回 503；客户端重试完整原请求。两条写入路径都支持在一个批中提交 start、事实和 done。

### 读取、失败与持久性

`GET /v1/sessions` 返回已提交任务摘要，至少含 session、title、project、status 和 last_seq。以 session 升序分页，参数 after_session 为上一页最后一个 session（省略从头），limit 默认 200、最大 200，返回 `{sessions:[...]}`。 `GET /v1/sessions/{session}/events?since_seq=N&limit=L` 从严格大于 N 的第一条事件开始返回升序事件，N 默认 0，L 默认 200、最大 200。返回 `{events,last_seq,status}`，结果和游标来自同一读快照；未知任务返回 404。分页以最后一条实际收到的 seq 为下一次 since_seq，直到追上 last_seq。第二阶段可使用轮询或 Tauri 通知唤醒读取；通知失败后仍通过游标补齐。后续 WS 如启用，复用此读游标与相同的事件次序。

错误响应使用 `{error:{code,message,...details}}`。400 用于 JSON、形状、限制和类型校验（超过字节上限用 413），401 用于鉴权，404 用于读取不存在的任务，409 用于与已提交事实或生命周期冲突（seq_gap、seq_conflict、operation_conflict、write_mode_conflict、task_not_started、task_already_started、task_closed、invalid_reference、node_id_conflict、seq_exhausted），503 用于暂时无法持久化。涉及元素的错误附 0 基 index；涉及当前任务状态的 409 附事务前 last_seq（未知任务为 0）。显式写入按形状、模式、幂等/冲突、连续性、生命周期、节点规则检查，网关分配省略连续性检查。合法重试先匹配已存在条目再检查任务是否结束。

SQLite 以 (session, seq) 唯一键保护事实，以 (session, operation_id) 唯一键保护分配映射。事件、任务状态、seq 水位和操作映射在同一事务中写入。WAL 使用 synchronous=FULL；成功响应和 UI 通知只能在 commit 成功后发出。事务未成功提交时整批不可见；提交后响应丢失时完整重发仍得到成功回执。进程重启从同一库重建任务和有序前缀，历史读取与实时读取走同一事实流。UI 更新通知仅表示可能有新事件。

生产者在首发前持久化完整事件或操作，保持原内容与标识。超时、断连、503 后读取最新发现文件并指数退避带抖动重发。401 重新读取发现文件后重试一次，持续失败保留待发并报错。seq_gap 优先重送本地缓存中从 expected_seq 开始的缺失事件；本地缺失则报告阻塞并保留余项，不能填造事件或跳过缺口。其他 4xx 保留拒绝信息与待人工处理条目，同 session 后续依赖项暂停。保留原队列记录直到收到并确认保存成功回执。任何删除或修复队列的交互由后续产品化处理。

## MCP 映射

所有工具接收显式 session 与 operation_id，支持 quote、context。客户端对同一次逻辑操作重试时复用 operation_id，并使用同一持久队列。独立队列通过全局唯一 operation_id 区分各自操作，不能重建另一队列为该操作保留的 ts。一次 MCP 工具对应一条追加操作，服务进程持久化首次调用的 ts、规范化参数和原始操作，重复调用先比较规范化工具参数并复用原 ts。成功发送后仍保留操作参数及 seq 回执，以便进程重启后识别相同调用；提交映射保存在网关数据库。恢复过程按每个生产者在同 session 的本地队列顺序发送。同 session 的跨生产者依赖以服务器已提交回执为准。

| 工具 | 事件和映射 |
| --- | --- |
| trace_task_start(title, goal, project) | task.start |
| trace_intent(id, title, summary?) | capability.intent |
| trace_done(id, summary?) | capability.done |
| trace_api(id, capability?, signature, kind, summary?) | api.expose，capability 映射 capabilityId |
| trace_file(id, capability?, path, action, purpose?, add?, del?) | file.change，capability 映射 capabilityId，缺省 add/del 各为 0 |
| trace_call(from, to, kind?) | call.edge，缺省 kind 为 calls |
| trace_task_done(summary?) | task.done |

工具返回 committed（含 seq），或 queued（含 session 和 operation_id，已落盘但尚未获得网关确认）。本地队列写失败及确定性协议拒绝返回工具错误。工具重试或本地队列重启可获得最终回执，queued 不能被解释成任务已结束。Agent 明确开始任务并在实际工作结束后调用 trace_task_done。trace_done 专用于能力。

## 兼容性及验收

保留原信封、七种事件、演示投影、批量数组和 accepted/last_seq 响应字段。本规格更新 2026-10-13 主设计的隐式根、500ms 重排缓冲、相同 seq 直接丢弃、路径端点推断和五工具生命周期缺口。桌面预览尚无持久事件库需要迁移。内置演示保留样例 ID，生产者可用 UUID 避免跨任务碰撞。

- 原演示和双图投影行为继续通过现有测试，合法事件前缀重放结果一致。
- start 之前发事实失败，start、事实、done 同批成功；再次 start 或 done 后新增事件失败；已结束任务的相同事件仍可重试。
- 先提交 seq=1，发送 seq=3 收到 expected_seq=2，持久层和 UI 保持 seq=1。发送 2、3 后连续可见。包含合法头和坏尾的批不改变水位或状态。
- 同 seq 不同 JSON 键顺序可重试；改 ts 或 payload 返回 seq_conflict。相同 append operation_id 返回原 seq，改内容返回 operation_conflict。两种模式交叉写入失败。
- 两个生产者并发向同一 append 任务追加无依赖事实，取得不同连续 seq，重放只出现一次。追加事实与关闭竞争时，数据库提交顺序决定是否纳入任务。
- 使用进程终止分别覆盖提交前和提交后响应前，重启后前者整批缺失、后者完整可读，重发后无缺口且无重复。收到成功后立即终止进程，重启仍可按游标读出已确认事件。
- MCP 在网关关闭时返回 queued，重启 MCP 后同一 operation_id 仍可追踪。恢复网关后从实际 stdio 工具写入并在桌面显示正确任务、能力、证据与结束状态，重新打开桌面可继续读取。
