# MindTrail 本机网关协议与实现状态

本文件记录第二阶段网关的设计约束。事件形状、错误优先级和冲突行为以 [v1.md](v1.md) 为权威；本文件补充本机生命周期、存储和桌面约定。

## 当前状态

SQLite 存储、事务写入、游标读取、HTTP 路由与认证，以及 Windows 上的服务启动、发现文件和桌面生命周期已实现。桌面工作台已接入真实任务；隔离的真实桌面测试验证了 MCP 离线写入与恢复、正常退出、端口回退、追加写入及重启重放。进程强杀恢复已在隔离测试中验证，硬断电尚未验证；Windows 发布验收仍在进行。MCP 和生产者队列已实现，多设备同步不在本阶段。

## 身份、生命周期与发现

状态目录为当前用户主目录下 `.path-tracker`，数据库为 `mindtrail.sqlite3`，发现文件为 `endpoint.json`。平台主目录解析失败应报告错误。状态目录由进程独占文件锁保护，锁覆盖迁移、服务和发现文件生命周期；第二实例不得写库或覆盖发现文件。拒绝目录和关键文件的链接或 Windows reparse point，并保证只有当前用户及必要系统账户可以访问状态文件；权限无法建立时停止发布。

数据库首次创建时生成随机持久 `store_id`，迁移、身份及架构在同一事务中保存；重启和移动同一数据库保留身份，新建库产生新身份。未知较新 `user_version` 或迁移失败时停止启动并保留原文件。备份应使用 SQLite 一致性备份或完全关闭后处理，不能单独复制活动 WAL 库的主文件。

SQLite 初始化成功并监听后才发布发现。服务仅绑定 `127.0.0.1`，依次尝试 7391–7490，仅地址占用时尝试下一端口。每次启动产生至少 32 字节随机 token；发现文件包含 `port`、`token`、`version: 1` 和 `store_id`。以同目录私有临时文件写入、同步、原子替换，失败则停止服务。正常退出在持锁期间撤回本次发布；崩溃残留由下次启动替换。生产者读取发现并用健康检查核对版本及库身份；身份变化时暂停续传，保留队列。

## HTTP 约定

所有 v1 路由使用 Bearer token，常量时间比较；拒绝非本机 Host 和浏览器 Origin，不提供浏览器跨域授权或信任代理标头。响应不缓存。实际请求体最多 1 MiB，每批最多 200 条。`GET /v1/health` 返回版本和库身份；`POST /v1/events` 和 `POST /v1/append` 使用 v1 解码器与对应事务规划器。错误、回执和重试语义见 v1。

`GET /v1/sessions` 使用 BINARY session 升序键集分页，`after_session` 独占；`GET /v1/sessions/{session}/events` 使用严格大于 `since_seq` 的序号分页。页长默认及最大 200，非法页长返回 400，未知任务返回 404。路径段和查询值仅解码一次，支持斜杠、百分号和非 ASCII 标识。每个事件页的事件、水位和状态来自同一读快照；客户端用实际最后收到的序号续读。

## SQLite 事务与恢复

数据库包含 `store_meta`、`sessions`、`events`、`operations`、`nodes`。事件和操作映射以 session 与各自键唯一；操作映射引用已分配事件。采用 WAL，写连接 `synchronous=FULL`，所有连接启用外键，busy timeout 有限。每个写批在 IMMEDIATE 事务内读取元数据和历史索引，使用同一快照执行规划，将事件、操作映射、节点和任务状态原子提交；仅成功提交后确认或通知。比较使用解析结构，而不是 JSON 字符串。持久化失败返回 503，客户端可重发完整原批。

读取页使用事务快照，数据库或数据损坏不能伪装成空任务。进程重启后从提交的事件前缀恢复投影；通知只是刷新提示，丢失时以游标轮询补齐。

## 桌面集成

Tauri 和 HTTP 共用读取服务，前端不接收 token。提交后仅通知 session，启动、聚焦和通知时刷新，并每秒轮询兜底。切换任务时丢弃旧请求结果，读取失败保留已有前缀并显示错误。观察到库身份变化时清除真实任务缓存并重新加载。真实任务按完整事件前缀生成双图与证据；内置演示保持独立和可用。网关启动失败不阻止桌面演示，并显示可操作的简短错误。

Windows 实现以持锁状态下的私有同步临时文件句柄调用 `FileRenameInfoEx`，使用已准入目录的绝对卷 GUID 路径提交发现文件。写入完成后先调用 `FlushFileBuffers`；已有目标需先通过无跟随对象与 ACL 校验。重命名成功才转移临时文件清理责任，失败不预先删除旧目标。此句柄式 API 不提供 `MOVEFILE_WRITE_THROUGH` 标志；目前没有断电后目录项持久性的验证。
